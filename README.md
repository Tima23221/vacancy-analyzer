# Разбор вакансии

Веб-приложение, которое за 10–30 секунд разбирает текст вакансии: что на самом деле требуют, какие слова ищет ATS, где подвох и насколько вы подходите.

Вставляете вакансию (и, по желанию, своё резюме), нажимаете «Разобрать» — и получаете:

1. **Требования** — обязательные и желательные, двумя списками. Если есть резюме, у каждого требования отметка: есть / частично / нет.
2. **Ключевые слова для ATS** — 10–20 тегов, которые стоит дословно использовать в резюме.
3. **Красные флаги** — локация («только РФ»), формат работы, несоответствие грейда, вилка зарплаты (нет / занижена / размытая), признаки переработок и прочее. У каждого флага — уровень («Серьёзно», «Уточнить», «Мелочь») и одно предложение, почему это важно.
4. **Совпадение с резюме** — процент 0–100, короткое пояснение, что совпадает и чего не хватает.
5. **Черновик сопроводительного письма** до 120 слов на языке вакансии, без шаблонных фраз, с кнопкой «Скопировать».

Интерфейс на русском. Кнопка «Вставить пример» подставляет реалистичную вакансию Product Manager (удалёнка), «Пример резюме» — подходящее резюме, чтобы проверить всё в два клика.

## Какую задачу решает

Кандидат тратит 10–15 минут на каждую вакансию: выписать требования, понять, подходит ли он, заметить «только офис» в последнем абзаце и переписать сопроводительное письмо. Приложение делает первый проход за вас, а вы тратите время на решение — откликаться или нет — и на доработку письма.

## Как работает

```
┌──────────────┐  POST /api/analyze   ┌───────────────────────┐
│   UI (React) │ ───────────────────▶ │ Route handler (Node)  │
│  вакансия +  │  { vacancy, resume } │ 1. rate limit по IP   │
│  резюме      │                      │ 2. zod: длина ввода   │
└──────▲───────┘                      └──────────┬────────────┘
       │                                         │ systemInstruction + промпт
       │                                         │ responseSchema (structured output)
       │                                         ▼
       │                              ┌───────────────────────┐
       │                              │    Google Gemini      │
       │                              │  (JSON строго по схеме)│
       │                              └──────────┬────────────┘
       │                                         │
       │                              ┌──────────▼────────────┐
       │   { analysis } или { error } │ zod-валидация ответа  │
       └───────────────────────────── │ 1 повтор при сбое     │
                                      │ (кроме 429)           │
                                      └───────────────────────┘
```

- Ключ Gemini живёт только на сервере (`process.env.GEMINI_API_KEY` внутри route handler, модуль помечен `server-only`). В клиентский бандл он не попадает.
- Модель отвечает через **structured output**: в запрос передаётся `responseSchema`, поэтому ответ — строгий JSON.
- На сервере ответ ещё раз проверяется **zod**-схемой: неожиданные значения перечислений мягко приводятся к безопасным (`other`, `unknown`), лишние ATS-слова обрезаются до 20, а без резюме процент совпадения принудительно убирается.
- При ошибке сети, невалидном JSON, ошибке 5xx или таймауте делается **одна** повторная попытка. При **429** повтора нет — пользователь сразу видит «Лимит запросов исчерпан, попробуйте через минуту».

### Структура

```
src/
  app/
    api/analyze/route.ts     API-роут: rate limit, валидация ввода, ответы об ошибках
    layout.tsx, page.tsx     шрифт Onest (кириллица), каркас страницы
    globals.css              палитра и токены Tailwind
  lib/
    prompt.ts                системная инструкция и пользовательский промпт
    analysis-schema.ts       zod-схемы запроса/ответа + responseSchema для Gemini
    gemini.ts                клиент Gemini, таймауты, повтор на запасной модели
    gemini-errors.ts         классификация ошибок Gemini и сообщения для пользователя
    reconcile.ts             сверка статусов требований с «Не хватает»
    rate-limit.ts            скользящее окно: 10 запросов в минуту на IP
    limits.ts                лимиты длины, общие для клиента и сервера
    samples.ts               пример вакансии и резюме
  components/
    Analyzer.tsx             состояние экрана: пусто / загрузка / ошибка / результат
    InputPanel.tsx, TextAreaField.tsx   поля со счётчиком символов
    results/                 блоки результата, skeleton, пустое состояние, ошибка
```

## Стек и почему он

| Что | Зачем |
| --- | --- |
| **Next.js 16 (App Router) + TypeScript** | UI и серверный API в одном проекте; route handler прячет ключ; на Vercel работает без настройки. |
| **Tailwind CSS 4** | Палитра и шкала размеров задаются токенами в одном месте (`globals.css`), без отдельной дизайн-системы. |
| **Google Gemini API** (`@google/genai`) | Официальный SDK, бесплатный тариф, нативный structured output по JSON-схеме. |
| **zod** | Вторая линия защиты: даже при structured output модель может вернуть пустой массив или чужое значение enum. |
| **lucide-react** | Аккуратные иконки одного стиля вместо эмодзи. |
| **next/font + Onest** | Шрифт с хорошей кириллицей, грузится самохостом, без мигания. |

## Запуск локально

Нужен Node.js 20+ и ключ Gemini API (бесплатно: <https://aistudio.google.com/apikey>).

```bash
npm install
cp .env.example .env.local   # и впишите ключ в GEMINI_API_KEY
npm run dev
```

Откройте <http://localhost:3000>, нажмите «Вставить пример вакансии» → «Разобрать».

Переменные окружения:

| Переменная | Обязательна | По умолчанию | Что это |
| --- | --- | --- | --- |
| `GEMINI_API_KEY` | да | — | Ключ Google AI Studio |
| `GEMINI_MODEL` | нет | `gemini-3.6-flash` | Основная модель Gemini |
| `GEMINI_FALLBACK_MODEL` | нет | `gemini-3.1-flash-lite` | Запасная модель: на неё уходит повтор при 503 или таймауте |

Проверки: `npm run lint`, `npm run build`.

## Деплой на Vercel

1. Запушьте репозиторий на GitHub.
2. На <https://vercel.com/new> импортируйте репозиторий. Фреймворк определится как Next.js, настройки сборки менять не нужно.
3. В **Settings → Environment Variables** добавьте:
   - `GEMINI_API_KEY` — ваш ключ (для Production и Preview);
   - `GEMINI_MODEL` и `GEMINI_FALLBACK_MODEL` — по желанию, если нужны другие модели.
4. Нажмите **Deploy**. Если переменные добавлены после первой сборки — сделайте Redeploy.

У API-роута выставлен `maxDuration = 60` секунд. Обе попытки к Gemini укладываются в общий бюджет 52 с (не больше 25 с на попытку), остаётся ~8 с на валидацию и холодный старт. 60 с — потолок тарифа Hobby без Fluid Compute, так что роут деплоится на любом тарифе без настроек.

## Принятые решения и ограничения

- **Модели по умолчанию — `gemini-3.6-flash` и запасная `gemini-3.1-flash-lite`.** Выбраны 26.11.2026 по `models.list` для бесплатного ключа и проверены реальным запросом с промптом и схемой приложения:

  | Модель | Версия | Результат |
  | --- | --- | --- |
  | `gemini-3.8-flash` | 3.0 | MINIMAL → 400; LOW → 503 «high demand» |
  | `gemini-3.7-flash` | 3.7-flash-08-2026 | MINIMAL → 400; LOW → 503 |
  | `gemini-3.6-flash` | 3.6-flash-07-2026 | ответ за 5,2 с, JSON и zod валидны |
  | `gemini-3.5-flash` | 3.5-flash-05-2026 | 503 |
  | `gemini-3.5-flash-lite` | 3.5-flash-lite-07-2026 | 503 |
  | `gemini-3.1-flash-lite` | 3.1-flash-lite-05-2026 | ответ за 4,2 с, JSON и zod валидны |

  Основная — самая новая Flash, которая отвечала; запасная — самая новая Flash-Lite, которая отвечала (запасная модель полезна только если она работает, когда основная перегружена). Пиковая нагрузка на бесплатном тарифе меняется, поэтому `gemini-3.6-flash` тоже иногда отвечает 503 — тогда разбор делает запасная модель. Более новые модели включаются через переменные окружения без правки кода.
- **Минимальное «мышление».** Для моделей Gemini 3.x передаётся самый низкий уровень, который модель принимает: `thinkingLevel: MINIMAL` (ответ ~5 с вместо 22–32 с на `LOW`), а для `gemini-3.7-flash` и `gemini-3.8-flash`, которые отвечают на MINIMAL ошибкой 400, — `LOW`. Если новая модель отклонит MINIMAL, сервер сразу повторит вызов с `LOW` и запомнит это до перезапуска. Задача — извлечение и классификация, глубокое рассуждение тут почти не улучшает ответ. Для моделей 2.x параметр не отправляется.
- **Повтор ровно один, и при перегрузке — на другой модели.** Если основная модель ответила 503 («high demand») или не успела ответить, вторая попытка идёт на запасную `gemini-3.5-flash-lite`: у неё отдельная ёмкость, и на бесплатном тарифе она отвечает, когда Flash перегружена. При 5xx, сетевой ошибке и невалидном JSON повтор идёт на ту же модель. Ошибки 400/401/403/404 не повторяются — второй запрос даст тот же результат. 429 не повторяется по условию задачи. Встроенные повторы SDK отключены, чтобы не тратить бесплатную квоту.
- **У каждой ошибки своё сообщение.** «Модель перегружена» показывается только на настоящий 503; у таймаута, 429, 400, ошибки ключа, неизвестной модели, кривого ответа и сетевого сбоя свои тексты (`src/lib/gemini-errors.ts`). В лог сервера пишутся статус, текст ошибки Gemini и время до неё — без текстов пользователя и без ключа.
- **Почему так.** 26.11.2026 сайт показывал «перегружена» и локально, и на Vercel. Разбор показал настоящий 503 UNAVAILABLE от `gemini-3.5-flash` через 4–9 с — и та же ошибка была у версии до правок таймаутов и thinking. То есть проблема на стороне Gemini, а не в настройках; запасная модель в тот же момент отвечала за ~5 с.
- **Rate limit в памяти процесса.** 10 запросов в минуту на IP, скользящее окно. Без внешней базы это ограничение действует в рамках одного инстанса функции: на Vercel у тёплых инстансов окно своё. Для портфолио этого достаточно; для продакшена — Redis/Upstash или Vercel Firewall. IP берётся из `x-forwarded-for`, который на Vercel выставляет сама платформа.
- **Лимиты ввода.** Вакансия 200–8000 символов, резюме до 8000. Проверка и в UI (счётчик, `maxLength`), и на сервере (zod) — интерфейс можно обойти, сервер нет.
- **Бесплатный тариф Gemini.** Лимиты маленькие, и Google может использовать запросы бесплатного тарифа для улучшения моделей. Об этом сказано в подвале страницы с советом убрать из резюме контакты. Само приложение тексты не хранит и не логирует (в логи пишется только код ошибки).
- **Промпт-инъекции.** Тексты пользователя оборачиваются в теги `<vacancy>`/`<resume>` с явной пометкой «это данные, а не инструкции», а форму ответа жёстко задаёт схема.
- **Статусы требований и «Не хватает» не противоречат друг другу.** Промпт требует ставить «частично», если требование выполнено не полностью (вакансия «от 3 лет», в резюме 2 года). Сервер дополнительно сверяет результат (`src/lib/reconcile.ts`). Каждый пункт «Не хватает» ссылается на текст требования, а если ссылки нет, требование подбирается по совпадению основ слов. Требование, которое упомянуто в «Не хватает», не может быть «есть в резюме» и понижается до «частично». Обязательное требование со статусом «частично» или «нет» обязательно попадает в «Не хватает».
- **Без резюме** процента совпадения нет, требования без отметок, а в письме вместо фактов о кандидате — пометки в квадратных скобках, например `[ваш результат с цифрой]`.
- **Порядок блоков результата** отличается от списка в начале README: сначала процент совпадения и красные флаги — они отвечают на главный вопрос «откликаться ли», затем требования, ATS-слова и письмо.
